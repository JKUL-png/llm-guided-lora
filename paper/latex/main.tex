\begin{abstract}
Can a frontier language model that diagnoses a small model's failure choose better places to train it than chance? Qwen3.5-0.8B loops in thinking mode until it hits its token limit. We trained \NLora{} LoRA adapters on the same \NExamples{} examples, each with exactly \ParamsLora{} parameters, and varied only which layers were trained: layers chosen by an informed Claude Opus session, random layers, a gradient-norm rule, a rule based on a layer sweep, Opus reading that sweep, and all \NModelLayers{} layers, with four seeds per arm. Every adapter escaped the loop: responses at the limit fell from \R{mod:math:06:T:lim}\% to \R{rng:mod:math:06:lim:min}--\R{rng:mod:math:06:lim:max}\%. On \NMath{} fixed MATH-500 problems, Opus's layers scored \R{cmp:math:06:b:c:dif} points against random layers \R{cmp:math:06:b:c:ci} and \R{cmp:math:06:b:d:dif} against the gradient rule \R{cmp:math:06:b:d:ci}, and our pre-specified criterion for a guided advantage was not met. No adapter beat simply turning thinking off on MATH. On GSM8K all adapters beat it by \R{rng:cmp:gsm8k:06:N:min} to \R{rng:cmp:gsm8k:06:N:max} points, but tied with a published weight edit of the same model; on IFEval they scored \R{rng:cmp:ifeval:06:P:absmin} to \R{rng:cmp:ifeval:06:P:absmax} points below that edit. Exploratory analyses suggest that the place does matter: the sweep rule beat the gradient rule by \R{cmp:math:06:e:d:dif} points \R{cmp:math:06:e:d:ci}, and the share of clean responses ranged from \R{rng:clean:math:min}\% to \R{rng:clean:math:max}\% across arms, lowest for Opus's layers. The place seems to matter, but Opus did not find a better one than chance.
\end{abstract}

\section{Introduction}\label{sec:1}

A natural use for a model that can read another model's internals is to decide where to intervene. A recent blog post by doubleAI places a coding agent inside training to find what a network fails to learn and to add code where it is needed \citep{doubleai2026}. Work on weight-space programming has a frontier model read and edit the weights of small networks directly \citep{takehi2026}. Both raise a question that is cheap to state and easy to get wrong: does the diagnosis help, compared with a choice that involves no diagnosis at all?

We study one concrete version of that question, on a model with a known, measurable failure. In thinking mode, Qwen3.5-0.8B often repeats itself until it reaches its token limit, so it rarely answers. In earlier work we showed that much of what a published weight edit gains on this model can be recovered by cheap baselines such as turning thinking off \citep{giraldo2026}. Here we keep the remedy fixed and vary only the place. The remedy is a LoRA adapter \citep{hu2022} trained to leave a loop and answer. The place is which four of the model's \NModelLayers{} layers the adapter trains. An informed Claude Opus session investigates the model with measuring tools and chooses four layers. We compare its choice with four layers drawn at random, four layers chosen by a gradient-norm rule, and two rules based on a systematic sweep in which each layer is switched off. Every adapter has exactly the same number of parameters and is trained on the same data, with the same steps and learning rate.

The design borrows the logic of a placebo. If the layers chosen by Opus help because Opus understood the network, they should beat random layers trained in exactly the same way. They should also beat a cheap automatic rule; otherwise the diagnosis adds cost and nothing else. We fixed the primary comparison and the criterion for a guided advantage before evaluation, in a plan kept in a local git repository. We call these \emph{pre-specified}; the repository has no external timestamp, so we do not call them pre-registered. We say plainly which analyses were decided after seeing results (\S\ref{sec:3.7}). An AI-assisted skeptical review of the analysis led us to adopt more conservative statistics, and we report them as primary.

\textbf{Contributions.}

\begin{enumerate}[nosep,leftmargin=*]
\item A controlled test of LLM-guided layer selection: \NArms{} arms, \NLora{} adapters, equal parameters, data and training, four seeds, and a random-layer placebo (\S\ref{sec:3}).
\item Two automatic arms that separate measuring from interpreting: a rule that reads a layer sweep, and Opus reading the same sweep (\S\ref{sec:3.3}).
\item Evaluation on MATH-500, GSM8K and IFEval against two cheap references, turning thinking off and a published weight edit (\texttt{p50c}), with intervals that count the variation between adapters (\S\ref{sec:4}).
\item An explicit account of what was fixed before and after seeing results, and of the corrections that followed an external-style review (\S\ref{sec:3.7}).
\end{enumerate}

\textbf{Findings.}

\begin{itemize}[nosep,leftmargin=*]
\item \textbf{Opus did not beat random layers or the gradient rule.} The differences on MATH are \R{cmp:math:06:b:c:dif} \R{cmp:math:06:b:c:ci} and \R{cmp:math:06:b:d:dif} \R{cmp:math:06:b:d:ci} points, and the pre-specified criterion for a guided advantage was not met (\S\ref{sec:4.2}).
\item \textbf{Every adapter escapes the loop, but none beats turning thinking off on MATH} (\S\ref{sec:4.1}, \S\ref{sec:4.3}). On GSM8K every adapter does, and all tie with \texttt{p50c}; on IFEval they are below \texttt{p50c} (\S\ref{sec:4.4}).
\item \textbf{The place seems to matter} (exploratory). A sweep-based rule beats the gradient rule, and the share of clean responses varies widely across arms, with the layers chosen by Opus lowest (\S\ref{sec:4.5}).
\end{itemize}

The place seems to matter, but Opus did not find a better one than chance.

\section{Background and related work}\label{sec:2}

\textbf{Weight-space programming and our earlier audit.} Takehi et al. describe experiments in which a frontier LLM reads the weights of small networks and edits them by reasoning, without gradient descent \citep{takehi2026}. In the best-known one, an edit to two tensors of Qwen3.5-0.8B raises its MATH-500 accuracy in thinking mode from a low base, because the unedited model mostly loops until it hits the token limit. In earlier work we rebuilt that edit (\texttt{p50c}: \MitEntries{} changed entries in \texttt{mlp.down\_\allowbreak{}proj} of layers \MitLayerA{} and \MitLayerB{}) and showed that cheap baselines recover much of its gain \citep{giraldo2026}. A public audit of the original logs motivated several of those controls \citep{messing2026}. We reuse that edit here only as a reference point, \texttt{p50c}, and its results come from the earlier study with the grading rule of this paper (\S\ref{sec:3.5}). The unedited model's loops are documented on its model card, which also notes that it runs in non-thinking mode by default \citep{qwen2026}.

\textbf{An agent that decides where to intervene (doubleAI).} The question behind this paper comes from a blog post by doubleAI \citep{doubleai2026}. In the post, a coding agent is placed inside training. It looks at how the network is learning, finds what it does not learn, and inserts small exact programs (``code layers'') behind a gate that starts at zero, so that inserting them does not change the network; ordinary training then decides whether to open the gate. Two of their experiments do not change weights at all, but control sampling (a linear probe on activations that triggers re-sampling, and a Python policy written by the model). The post describes two controls that we borrow in spirit. A \emph{twin} is, in their words, ``an identical run from the same checkpoint on the same batches, with the new layer switched off''. A \emph{sham} ``keeps the layer's shape and parameters but scrambles the information it carries''. Our design differs in three ways. First, we do not insert code: we choose which layers of a LoRA adapter to train, so the agent's product is a place, not a program. Second, our placebo is not a sham. A sham keeps the place and damages the information; our placebo keeps the data and draws the place at random, so it tests whether \emph{where} matters, not \emph{what}. Our nearest equivalent to a twin is the same seed, the same data and the same steps with other layers, together with the untrained model. Third, for every arm we report the items that the post's text, as far as we could find, does not state for its experiments: the number of seeds, uncertainty intervals, sampling temperature and per-experiment sample sizes (a few sample sizes are given in places). We cite only what is visible in the post, and we do not claim that an item is absent from the experiments themselves, only that we did not find it in the text.

\textbf{Edits against adapters trained on the same data.} A figure from a web page on ``weight-patching'' \citep{kevinpl07weightpatching}, which is all we saw of it, compares a weight edit with a LoRA trained on the same data on four bugs. Its title reads ``Fine-tuning fixes the bug too. But it changes everything else.'' Its caption says that LoRA ties or wins on the bug in three of four cases, while the edit wins on side effects, and that a random edit of the same size does nothing. The suspicion is the same as ours: a sophisticated intervention should be set against a cheap baseline trained on the same data. The setting is different in every way that matters. They compare an edit with a LoRA; we compare ways of \emph{choosing the layers} of a LoRA. Their figure states greedy decoding and shows no intervals or sample sizes, while we sample with temperature and four seeds. Their random edit is an edit, not a LoRA, so it is not our placebo. We therefore do not use it as evidence for or against our result.

\textbf{Choosing where to adapt.} Parameter-efficient fine-tuning with LoRA \citep{hu2022} leaves open which layers to adapt. Existing methods decide where to spend the parameter budget by importance scores computed during training \citep{zhang2023adalora}, or by sampling which layers to update according to their importance \citep{pan2024lisa}. Work on locating and editing facts points at MLP layers in the middle of the network \citep{meng2022rome} and describes feed-forward layers as key-value memories \citep{geva2021ffn}, which is part of why we restrict our adapters to the MLP. Directional ablation shows that a behavior can sometimes be removed by a rank-one edit \citep{arditi2024}. None of this asks whether a language model, given a diagnosis task, picks better layers than chance, and that is the question here. Our gradient-norm arm is a simple member of the first family; our sweep arm is closer to ablation-style localization.

\textbf{Handling loops and test-time control.} Forcing a model to end its thinking is a simple way to control test-time compute \citep{muennighoff2025}. We use the same idea as a \emph{teacher}, not as an inference trick: the training examples are loops cut at the first copy and closed by hand (\S\ref{sec:3.2}).

\textbf{Benchmarks and tools.} MATH-500 is the 500-problem subset of MATH \citep{hendrycks2021} used by \citet{lightman2023}. We also use GSM8K \citep{cobbe2021} and IFEval \citep{zhou2023}. Generation uses vLLM \citep{kwon2023}, and grading uses math-verify \citep{mathverify} and the lm-eval IFEval checker \citep{lmeval}. For statistics we use Wilson intervals \citep{wilson1927}, exact McNemar tests \citep{mcnemar1947}, Holm's correction \citep{holm1979}, the bootstrap \citep{efron1979} and a randomization test in the tradition of \citet{fisher1935}.

\section{Methods}\label{sec:3}

\subsection{Design}\label{sec:3.1}

The question is whether a language model that diagnoses the problem and picks the layers to adapt does better than choosing the layers at random or by a cheap automatic rule. We train \NLora{} LoRA adapters: \NArms{} arms, each with \NSeeds{} seeds. All arms train on the same data, in the same order for a given seed, for the same number of steps and with the same learning rate. All adapters have exactly \ParamsLora{} trainable parameters. Only the layers differ, and the rank that equalizes the parameter count. Table~\ref{tab:arms} lists the arms.

The contrasts that isolate the choice of layers are among the four-layer arms (b)--(f). Arm (a) is a reference: it differs from the rest in the layers \emph{and} in the rank (\RankFull{} against \RankFour{}), so a difference with (a) cannot be attributed to either. The original model, with thinking and without thinking, and the \texttt{p50c} edit of earlier work, are fixed references in every table (\S\ref{sec:3.5}). Turning thinking off is the cheap baseline that the earlier work showed to be strong \citep{giraldo2026}; it must therefore be in every comparison.

\subsection{Model, adapters and training data}\label{sec:3.2}

\textbf{Model and adapter.} All experiments use Qwen3.5-0.8B, which has \NModelLayers{} blocks, each with an MLP part. LoRA is applied to the MLP projections only. This choice makes the parameter count exactly comparable. If LoRA touched every module, a layer with linear attention and a layer with full attention would cost different numbers of parameters per rank, and two groups of layers could not be given the same budget. With MLP-only adapters every layer costs \ParamsPerRankLayer{} parameters per unit of rank, so $\NLayersFull \times \RankFull$ and $\NLayersFour \times \RankFour$ both give \ParamsLora{} (checked with the formula and with the PEFT library). The scaling factor $\alpha$ is twice the rank (\AlphaFull{} and \AlphaFour{}).

\textbf{Training data: cut and close.} The model loops, so it almost never produces a finished, correct response that could serve as a training example. We therefore use the ``cut and close'' recipe of our earlier work. The unedited model is run on \NTrainProblems{} problems from the MATH training set (disjoint from MATH-500; the data builder rejects any evaluation problem). When a response loops, a detector finds the first copy of the repeated passage. We cut the text there, append a fixed closing sentence and the end-of-thinking tag \texttt{</think>}, let the model write its answer, and keep the example only if math-verify marks the answer correct. Responses that finish on their own and are correct are also kept. The result is \NExamples{} examples (\NForced{} forced and \NNatural{} natural; \NDroppedLong{} dropped for length), with \NTrainTokens{} tokens in total and a maximum length of \MaxTrainTokens{} tokens. The teacher is the unedited model itself, not \texttt{p50c}, so that the MIT edit does not enter any arm. GSM8K and IFEval are never used for training; they measure transfer and forgetting.

\textbf{Training.} The loss counts only on the closing sentence and the answer. The earlier text is read but not trained on. This avoids reinforcing the path that led into the loop, and it makes memory use manageable, because the vocabulary has \VocabSize{} tokens and full-sequence logits would not fit on the GPU. Each adapter is trained for \Epochs{} epoch (\TrainSteps{} optimizer steps with gradient accumulation \Accum{}) at learning rate $\LearningRate$. The learning rate was fixed in advance, and the pilot only checked that training did not diverge. Training runs under WSL2 on a single 8 GB consumer GPU. The seed fixes the order of the data and the sampling of evaluation, and in some arms also the layers (\S\ref{sec:3.3}).

\subsection{How the layers are chosen}\label{sec:3.3}

\textbf{(c) Random placebo.} The layers are drawn as \PlaceboRule{} for seed $s$. The draw was saved before any diagnosis and the trained layers match the saved file (checked by the macro script). Each seed has a different group of layers.

\textbf{(d) Gradient-norm rule.} In the unedited model, we compute for each layer the sum of the raw gradient norms of its three MLP matrices over \GradExamples{} training examples drawn with the seed, and keep the four layers with the largest sum. The relative norm (divided by $\|W\|$) is recorded but not used.

\textbf{(b) Opus, informed.} A fresh Opus session investigates and then chooses four layers with reasons. The session runs outside this repository, in an isolated directory, and can only use a fixed set of tools: free commands to read the context and the help; short queries (activations, gradients, switching off a layer, a logit lens); and a command to generate samples (up to \MaxTokensEval{} tokens, several problems and samples per call, with the option of switching off the MLP of a layer). It sees only \SweepDiagProblems{} problems from the MATH training set, never an evaluation problem. The budget is the same for every session: \OpusShortQueries{} short queries, \OpusLongSamples{} long samples and \OpusMaxCalls{} calls. The context (about \OpusContextWords{} words) contains the recipe, how the result will be measured, and summaries of the blog post of the original authors, of paper 1 and of the doubleAI post (only what is visible in it). It contains only aggregate numbers and no evaluation problem, and it does not contain the placebo draws, the layers of other arms, or the outputs of other sessions and of the pilot adapter. It does name layers \MitLayerA{} and \MitLayerB{}, the layers that the MIT edit changes. This is an \emph{anchoring} risk: Opus may choose them because it read them. We report it. Across the four sessions, layer \MitLayerA{} was chosen in \OpusLayerFifteen{} and layer \MitLayerB{} in \OpusLayerNineteen{}, and two sessions share on average \OpusSharedMean{} of their four layers (\OpusSharedChance{} would be expected by chance). The sessions are independent and have no memory. Each seed uses one session; the mapping is in Table~\ref{tab:arms} and in the list file. A rule fixed in advance decided whether two sessions were enough (if the first two shared at least three of their four layers) or four were needed. For (b) the first two sessions did not (any two sessions share at most \BSharedFirstTwoMax{} layers), so four were run.

Two asymmetries are part of the cost of ``guided'' and are reported: (b) and (f) receive a context and (for (b)) hours of GPU time through the tools, while (c), (d) and (e) do not.

\textbf{(e) Automatic sweep.} This arm separates \emph{measuring} from \emph{interpreting}. The system, not Opus, measures every layer. The sweep uses the \SweepResponses{} diagnostic responses that reach the token limit. In each one, the loop detector of paper 1 marks where the loop starts, and we take \SweepFragPerResp{} fragments: the cut point at the first copy and \SweepExtraPoints{} more at paragraph (or line) ends spread across the loop. That makes \SweepFragments{} fragments, plus \SweepControl{} responses that do close on their own, used as a descriptive positive control. For each fragment we run forward passes (no generation) under \SweepConditions{} conditions: the normal model and, for each of the \NModelLayers{} layers, its MLP output replaced by zero or by its mean. The main metric is the change in $\log P(\texttt{</think>})$ as the next token. Two secondary metrics are the change in the log-probability of the full closing sentence and of the next \SweepContTokens{} real tokens. Per-layer means have bootstrap intervals over problems, because the fragments of one response are not independent. The rule, fixed before measuring, takes the four layers with the largest mean absolute change in the main metric under zeroing.

\textbf{(f) Opus reading the sweep.} Opus receives the same context as in (b) plus the sweep table, but no measuring tools and no GPU. It reads the table and chooses four layers with reasons. The same two-or-four rule applies; the first two sessions shared \FSharedFirstTwo{} of four layers, so two sessions were used, each for two seeds. Without (e), (f) could not be judged: if Opus picked the same four layers as the rule, its interpretation would add nothing.

\subsection{Merging and size of the edit}\label{sec:3.4}

Each adapter is merged into the base weights and the merged model is saved in bfloat16, so that vLLM evaluates a model with edited weights. Rounding to bfloat16 could erase a small update, so we measure the smallest fraction of the update that survives rounding (\MinKept{} over all tensors and adapters). We report, as descriptive numbers, the largest $\|\Delta W\|/\|W\|$ per tensor after merging for each arm: \DWaLo{}--\DWaHi{} for (a) and \DWfourLo{}--\DWfourHi{} across the four-layer arms. These are not tests, and arms with the same parameter count can still change the weights by different amounts.

\subsection{Evaluation and grading}\label{sec:3.5}

\textbf{Problem sets.} Evaluation uses the fixed subsets of paper 1, chosen once and never regenerated: \NMath{} MATH-500 problems (stratified by difficulty level, with \MathLevels{} problems at levels 1 to 5; selection seed \MathSubsetSeed{}), \NGsm{} GSM8K problems (the first of two subsets) and \NIfeval{} IFEval prompts. No evaluation problem enters training or diagnosis. Every arm uses exactly these problems, with four sampling seeds ($\NMath \times \NSeeds = \NPairs$ (problem, seed) pairs per arm and task). With \NMath{} problems, one run has a 95\% interval of about $\pm$\WilsonHalf{} points near 50\%, so we do not read small differences.

\textbf{Generation.} Evaluation uses vLLM under WSL2 on the merged models. The prompt is the problem, a newline, and ``Please reason step by step, and put your final answer within \textbackslash{}boxed\{\}.'' Table~\ref{tab:config} gives the configurations. All LoRA arms use the thinking configuration of the original authors at $T=\TempMain$, with presence penalty \PresencePenalty{} and a limit of \MaxTokensEval{} tokens, and the seed of the LoRA is the sampling seed. The temperature $T=\TempHigh$ was measured only for the best arm at $T=\TempMain$ (chosen by a rule fixed in advance: highest mean accuracy over four seeds, ties broken by fewer responses at the limit) and for the references. GSM8K and IFEval were measured only at $T=\TempMain$ (\S\ref{sec:3.7}).

\textbf{References.} T: the unedited model with thinking. N: the unedited model with thinking off, same sampling and \MaxTokensEval{} tokens. P: \texttt{p50c}, the MIT edit, with thinking. They are in every comparison. T and P come from the earlier study with the same fixed problems and four seeds, and were re-graded with the rule below.

\textbf{Grading.} The final answer is the text after the \emph{last} \texttt{</think>}. In thinking mode, a response without \texttt{</think>} is wrong; without thinking there is no tag, and the whole text counts as the answer. For MATH and GSM8K we take the last \texttt{\textbackslash{}boxed\{\}} and compare it with math-verify 0.9.0 \citep{mathverify}; no box is wrong. For IFEval we apply the official checker to that answer. The rule is the same for all arms and references. Our earlier study took the text after the \emph{first} \texttt{</think>}. The rule used here was fixed before the real evaluation, but after we saw that a pilot LoRA sometimes closes its thinking more than once. To check that the choice does not matter, we graded all LoRA responses on MATH and GSM8K with both rules: they agree on \RuleSame{} of \RuleItems{} responses.

\textbf{Metrics.} For every arm we report accuracy, the share of responses that reach the token limit, mean tokens, the share of responses with more than one \texttt{</think>}, accuracy among the responses that finish, and the size of the merged edit. Two quantities are exploratory and were defined after seeing the data: a \emph{clean response} (exactly one \texttt{</think>} and not at the limit), and the gain split between problems where the original thinking model hit the limit and those where it finished.

\subsection{Statistics}\label{sec:3.6}

The unit of analysis is the problem. The four seeds of the same problem are not independent, and neither are the four LoRAs of the same arm, which differ in layers, training seed and sampling at once. Our primary interval is therefore a \textbf{two-way bootstrap}: it resamples the problems and, separately, the seeds of each arm (\BootTwoWayReps{} resamples, fixed seed \BootTwoWaySeed{}); it counts that a different LoRA would give a different number. With only four LoRAs per arm it is crude and probably somewhat narrow. As a robustness check we also report the bootstrap over problems alone (\BootProblemReps{} resamples, seed \BootProblemSeed{}). Our primary test is an \textbf{exact sign-flip permutation test by problem}: for each problem we sum correct answers over the four seeds for arm X minus arm Y and compare the sum with its distribution when the sign of each problem's difference is flipped independently. p-values are corrected with Holm's method within the family stated in each table. The McNemar test on the \NPairs{} (problem, seed) pairs, which was our first choice, treats those pairs as independent. This pseudo-replication makes its p-values too small, so we keep it only as a robustness check. A comparison of four LoRAs against four LoRAs (each LoRA as one observation) is also given; its smallest possible p-value is \LoraMinP{}.

Primary comparisons were fixed in advance: (b) against (c) and (b) against (d) on MATH at $T=\TempMain$, with a Holm family of two, and every arm against the no-thinking original on each task. Everything else is exploratory. After the external review we adopted a reading rule for the results: a difference is \emph{solid} only if the Holm-corrected permutation p-value is below \HolmAlpha{} \emph{and} the two-way interval excludes zero; if only one holds it is an \emph{indication}. The rule was chosen after seeing the data. Because ``did not beat'' is not ``is equal to'', we report the intervals, which bound how large an advantage could remain hidden.

\subsection{Every adapter escapes the loop}\label{sec:4.1}

Table~\ref{tab:models-math} and Figure~\ref{fig:1} give the per-model results on MATH at $T=\TempMain$. In thinking mode the original model answers \R{mod:math:06:T:acc}\% correctly, because \R{mod:math:06:T:lim}\% of its responses run into the \MaxTokensEval{}-token limit. All \NLora{} adapters escape this: their share of responses at the limit falls to \R{rng:mod:math:06:lim:min}--\R{rng:mod:math:06:lim:max}\%, and their accuracy is \R{rng:mod:math:06:acc:min}--\R{rng:mod:math:06:acc:max}\%. Everything in this subsection is exploratory. It suggests that the choice of layers does matter, even though Opus did not find a better choice than chance.

\textbf{Between automatic rules.} The sweep rule (e) is \R{cmp:math:06:e:d:dif} points above the gradient rule (d), with a two-way interval of \R{cmp:math:06:e:d:ci} and Holm \R{holm:pairs:math:e:d:hs} among the nine pairs of four-layer arms (Table~\ref{tab:explore}). Opus reading the sweep table (f) scored \R{cmp:math:06:f:e:dif} \R{cmp:math:06:f:e:ci} against the automatic rule that read the same table ($p=\R{cmp:math:06:f:e:p}$ before correction; Holm \R{holm:pairs:math:f:e:hs} among the nine pairs, \R{holm:central:math:f:e:hs} in the family of five we first planned for these comparisons). \subsection{Cost of choosing the layers}\label{sec:4.7}

Training and evaluation cost the same in every arm: \R{cost:train:min}--\R{cost:train:max} GPU minutes to train one adapter and \R{cost:eval:min}--\R{cost:eval:max} minutes to evaluate it on the three tasks at $T=\TempMain$. Arms differ in what it costs to choose the layers (\texttt{costo\_diagnostico.csv}). The \NLayersFull{}-layer adapter and the placebo cost nothing. The gradient rule took \R{cost:grad:gpu} GPU minutes for its four seeds. The sweep took \R{cost:sweep:gpu} GPU minutes, plus \R{cost:saved:gpu} minutes to generate the stored diagnostic responses. The \R{cost:inf:n} informed Opus sessions used up to \R{cost:inf:gpu} GPU minutes through their tools (an upper bound that includes a \R{cost:inf:hang}-minute hung generation) and an API-equivalent \$\R{cost:inf:usd} reported by the client; the \R{cost:ob:n} sessions that read the sweep cost \$\R{cost:ob:usd} and no GPU. The most expensive way of choosing layers did not do better than the free ones.

\section{Discussion}\label{sec:5}

\textbf{What the null result says.} In this setting, an informed Opus session that investigates the model and chooses four layers for a LoRA adapter did not beat four random layers or a gradient-norm rule. This holds under every test we tried: the pre-specified McNemar test, the permutation test, treating each adapter as one observation, all pairings of seeds, and both grading rules. It is a statement about this protocol, not about language models choosing where to train in general. The intervals leave room for a modest advantage that our four adapters per arm could not detect (\S\ref{sec:4.2}). The evidence does not, however, point towards one: on clean responses, the layers chosen by Opus are the worst of all arms.

\textbf{The place seems to matter.} The null result is not that ``any layers will do''. The automatic sweep beat the gradient rule by \R{cmp:math:06:e:d:dif} points, and the share of clean responses ranged widely across arms and even across the four random draws of the placebo. Both signals are exploratory and both involve arms chosen or defined after seeing data, so we read them as indications. Taken together they suggest that where the adapter goes changes what it learns, and that Opus did not find a better place than chance. A single sentence summarizes it: \emph{the place seems to matter, but Opus did not find a better one than chance}.

\textbf{Why might Opus not help?} Our data suggest three reasons, none of them tested directly. First, its evidence was thin: the whole budget of a session was \OpusLongSamples{} long samples, which is enough to see large effects but not differences of a few points. Second, its choices were unstable: two sessions share on average \OpusSharedMean{} of four layers, little more than the \OpusSharedChance{} expected by chance. Third, its context named layers \MitLayerA{} and \MitLayerB{}, and it chose layer \MitLayerA{} in \OpusLayerFifteen{} of four sessions and layer \MitLayerB{} in \OpusLayerNineteen{}, so its choices may partly reflect the hint rather than its own measurements. When the measuring was taken away from Opus and done by a fixed sweep, a mechanical reading of the sweep did at least as well as Opus reading the same table (\S\ref{sec:4.5}). That points at interpretation, not only measurement, as a weak link, but the comparison is exploratory.

\textbf{Against the cheap baselines.} Our earlier study found that turning thinking off recovers most of what a weight edit buys on this model \citep{giraldo2026}. The same holds for trained adapters. On MATH no adapter beats turning thinking off. On GSM8K every adapter does, but so does \texttt{p50c}, and the adapters are tied with it. On IFEval the adapters are no better than turning thinking off and are below \texttt{p50c}. What the adapters buy over the edit is mostly efficiency on math: they finish far more often and with far fewer tokens, and the one adapter we ran at $T=\TempHigh$ did not collapse there as \texttt{p50c} does.

\textbf{Relation to other work.} doubleAI asks whether an agent that diagnoses a network can decide where to intervene during training \citep{doubleai2026}. We test a narrow version of that question, with a placebo that keeps the data and draws the place, and the answer here is no advantage. Our placebo is not their sham, and our adapters are not their code layers, so this does not contradict their results; it shows that the question needs controls of this kind. The weight-patching figure \citep{kevinpl07weightpatching} reports that a LoRA trained on the same data ties or beats an edit on most bugs while changing more of everything else. We see a related pattern from the other side: the adapters match \texttt{p50c} on math but fall behind it on instruction following. We do not use either source as evidence for our result.

\section{Limitations}\label{sec:6}

\begin{itemize}[nosep,leftmargin=*]
\item \textbf{Few adapters.} Each arm has four adapters, and each group of layers was trained once. The seed fixes the training order, the sampling and, in arms (b), (c) and (f), the layers, so these sources of variation cannot be separated. The two-way bootstrap tries to account for them, but with four units it is crude and probably somewhat narrow.
\item \textbf{Analysis choices made after seeing data.} The Holm families, the pooling of seeds, the reading rule, the two-way interval, the permutation test and every comparison with \texttt{p50c} were chosen after seeing results (Table~\ref{tab:when}). We report alternative families in the repository (\texttt{revision/rev\_holm.csv}); the main conclusion does not change under any of them.
\item \textbf{Pre-specified, not pre-registered.} The plan lives in a local git repository without an external timestamp.
\item \textbf{Reduced scope.} The planned company-knowledge task was dropped after seeing the MATH results, and it is the task where the place of the adapter might have mattered most. Arm (b) was never evaluated at $T=\TempHigh$, so the ``guided wins'' criterion could only fail.
\item \textbf{No control for the data.} All \NLora{} adapters use the same \NExamples{} examples. No arm uses the same layers with other data, and there is no sham arm, so nothing here says how much of escaping the loop is due to the data recipe.
\item \textbf{Opus with a hint.} Arms (b) and (f) are Opus with context that names the layers of the MIT edit. No un-hinted Opus arm was trained, and the four informed sessions agree little with each other. Arms (b) and (f) also had information and compute that (c), (d) and (e) did not.
\item \textbf{Arm (a) is not a clean contrast.} It differs from the others in layers and rank at once.
\item \textbf{The sweep arm.} Arm (e) includes layer \R{layers:e:min}, whose removal damages the model broadly, and it was chosen as the best arm with the same data, so comparisons with it are inflated.
\item \textbf{References from another study.} The thinking original and \texttt{p50c} come from our earlier study \citep{giraldo2026}: same fixed problems, same sampling and four seeds, re-graded with this paper's rule.
\item \textbf{Small evaluation sets and one model.} \NMath{} problems per task, one model of 0.8B parameters and one training recipe. With these sets, differences of a few points are below what we can detect.
\end{itemize}

\section{Conclusion}\label{sec:7}

We asked whether a frontier model that diagnoses a small reasoning model's loops chooses better layers for a LoRA adapter than chance or a cheap rule. It did not: with equal parameters, data and training, Opus's layers did no better than random layers or a gradient-norm rule, and the pre-specified criterion for ``guided wins'' was not met. Every adapter escaped the loop, but on MATH none beat simply turning thinking off. Exploratory results suggest that the choice of layers does change what the adapter learns. In short, the place seems to matter, but Opus did not find a better one than chance. Settling this would need more random draws and retrainings of the same layers, a fake-data arm, and the guided arm at both temperatures; we have not run them.
